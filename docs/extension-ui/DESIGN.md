# Extension UI — дизайн-контракт

## Источники правды

1. Явные решения пользователя для Taptop Toolkit.
2. Этот файл и `anatomy.md` после их утверждения.
3. Shadcn preset `bbVK0Gm`: Maia, Neutral, Geist, Lucide, medium radius, default/solid menu, subtle menu accent. Конкретные значения — в `anatomy.md` (из реестра `radix-maia`).
4. Локальные UI skills и общие рекомендации.

Пресет задаёт анатомию и качество компонентного интерфейса. Он не добавляет в расширение React, Tailwind или shadcn runtime: Taptop Editor получает изолированный vanilla-JS/CSS слой.

## Решения для Toolkit

- Шрифт: локальный Inter Variable.
- Тема: светлая; тёмная тема не входит в MVP.
- Брендовый акцент: Taptop blue `#3290FF`; его hover/focus состояния определяются в `anatomy.md`.
- Базовая визуальная плотность: Maia — спокойная, скруглённая, с достаточным воздухом.
- Иконки: компактные SVG в духе Lucide, только с понятным `aria-label` на интерактивном контроле.
- CSS variables разрешены только в UI расширения. Они не попадают в экспортируемые сайты и не заменяют буквальные значения системы Taptop.

## Канонический путь импорта

1. На каждой странице редактора Taptop видна круглая синяя кнопка над штатной `?` справа внизу; подсказка «Импорт JSON». Иконка расширения в Chrome на вкладке редактора открывает тот же диалог.
2. Диалог «Импорт JSON» — пошаговый: файл → проверка → импорт → результат.
3. Внешние toast-уведомления не используются: весь ход операции в диалоге.
4. Успех показывается только по подтверждённому root layer. Ошибка до вставки — «На страницу ничего не добавлено» и «Повторить». Любой сбой после начала вставки — «Проверьте результат» без повтора.

## Импортные состояния

| Состояние | Экран | Доступные действия |
| --- | --- | --- |
| idle | «Импорт JSON» + зона «Перетащите JSON сюда» | Выбрать / перетащить файл, закрыть |
| validating | Зона: «Проверяем файл…» | Ожидание |
| invalid | Красная зона: «Файл не подходит», имя файла и причина по-русски | Выбрать другой, закрыть |
| ready | «Проверьте перед импортом»: файл, слои, классы (в строке — не больше двух чисел, «изменены вами» всегда видно; в раскрытом списке группы с точкой, числом и плашками имён, до 8 имён + «+N», свойства в подсказке, «без изменений» только числом; «Классы сайта» — классы проекта, которые файл использует по имени, с именами, перед «Без изменений»), изображения; если в проекте уже есть чужой класс с тем же именем — выбор «Копиями / Существующие / Обновить» с пояснением | Отмена / Импортировать (50/50), Заменить, выбор |
| invalid: нет классов сайта | Красная зона: «в проекте нет классов сайта: .a, .b…» (без «ничего не добавлено» — импорт ещё не начинался) | Выбрать другой файл, закрыть |
| preparing / uploading | Кольцо %, заголовок «Загружаем изображения n из N» | Ожидание, закрыть нельзя |
| inserting | Кольцо 85%, «Вставляем в Root» | Ожидание |
| confirming | Кольцо 95%, «Проверяем результат» | Ожидание |
| completed | «Импорт завершён» | Импортировать ещё / Готово |
| failed до вставки | «Импорт не выполнен» + причина + «На страницу ничего не добавлено.» | Другой файл / Повторить (если безопасно) |
| failed после начала вставки | «Проверьте результат» | Понятно; без повтора |

Во время импорта диалог не закрывается крестиком, фоном или Escape.

## Базовые компоненты MVP

| Компонент | Визуальный референс | Назначение |
| --- | --- | --- |
| Floating launcher | Button + Tooltip | Постоянный вход в импортёр |
| Import dialog | Dialog | Единственный контекст импорта |
| File field | Input + Button | Выбор JSON и имя файла |
| Primary action | Button | Запуск подтверждённого импорта |
| Progress status | Progress | Подготовка и загрузка N из N |
| Package summary | Badge + muted text | Слои, классы, изображения |
| Inline feedback | Alert-style status | Успех, ошибка, следующее действие |
| Divider | Separator | Ритм внутри диалога |

Перед созданием нового UI-примитива нужно проверить этот список и `inventory.md`. Составной экран строится из существующих примитивов.

## Проверка

- Путь: открыть редактор → увидеть launcher без клика по Chrome action → открыть диалог → выбрать JSON → пройти все статусы.
- Для каждого состояния: keyboard focus, Escape/close, reduced motion, контраст, читаемость текста и отсутствие перекрытия штатной кнопки `?`.
- Визуально проверять в самом Taptop Editor, а не только в изолированном HTML.
- Перед завершением UI-изменения обновлять `inventory.md` и сохранять скриншоты состояний.
